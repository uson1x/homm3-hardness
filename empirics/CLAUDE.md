# CLAUDE.md — homm3/empirics (эмпирика: оптимум против агентов)

Инструкция для следующего агента, который продолжит работу в этой папке.

## Что это

Эмпирическая часть статьи о сложности HoMM3. По `../LIT-REVIEW.md` §3.4 это
**единственный вклад работы, у которого не нашлось соседей в литературе**: никто
в жанре не меряет разрыв между точно вычисленным оптимумом и тем, как задачу
решают современные агенты.

Меряем ровно одно: на инстансах `ARMY-ALLOCATION` (`../MODEL.md` §9) сравниваем
**точный оптимум** с тем, что достигают эвристики и LLM-агенты. Решение агента —
только предбоевое распределение армии по слотам; сам бой после этого доигрывается
оптимально исчерпывающим перебором. Это сознательно щедро к агенту: мы не хотим
штрафовать его за тактику, которую он не выбирал.

## Правила работы

1. **Писать только внутри `homm3/empirics/`.** `../STATE.md` не редактировать,
   чужие репозитории (`AI/vcmi-*`, `AI/homm3*`) — строго read-only.
2. **Не делать git commit/push.** Этим занимается оркестратор.
3. **Механика — только из `../scripts/homm3_model.py`.** Не переписывать правила
   заново: любое расхождение с эталонной моделью — это баг здесь, а не улучшение.
4. **Ни одно число не идёт в отчёт без независимой проверки.** Протокол —
   `scripts/verify_instances.py`, он обязан давать `ALL PASS`.
5. Рабочие документы (`STATE.md`, `REPORT-DESIGN.md`) — по-русски; код и
   промпты — по-английски (промпты уйдут в статью и в прогон моделей).

## Как всё воспроизвести

```bash
python3 scripts/extract_creatures.py    # нужен установленный VCMI с данными H3
python3 scripts/gen_instances.py        # ~2 мин
python3 scripts/verify_instances.py     # ~5 мин, ожидается ALL PASS
python3 scripts/baselines.py            # ~2 мин
python3 scripts/make_llm_tasks.py
python3 scripts/test_scorer.py          # ожидается OK
```
Зависимостей нет, только стандартная библиотека Python 3.

## Что важно не сломать

- **`R = 1` во всех инстансах.** На этом держится корректность быстрого оценщика
  и релаксации в `solve.py` (см. docstring модуля). Инстансы с `R > 1` требуют
  другого решателя, генератор их не выпускает.
- **Плоский урон (`dmg_min == dmg_max`).** Требование `H3-det` (`../MODEL.md` §4).
- **Без стрелков и двухклеточных существ.** Эталонный симулятор их не реализует;
  включить их — значит публиковать числа, за которые модель не отвечает.
- **Сертификат оптимума.** `optima.json` хранит не только значение, но и
  распределение, на котором верхняя оценка достигается в симуляторе. Инстанс без
  сертификата в набор не попадает.
- **Оценка распределения — только `solve.play_optimally`, не `play_fast`.**
  Это стоило одной пойманной ошибки, и её стоит помнить. `play_fast` считает
  досягаемость по стартовой расстановке и ошибается **в обе стороны**: свой стек
  может перекрыть подход (тогда `play_fast` завышает), но стек, который уже
  сходил, **освобождает** свой гекс и открывает путь союзнику (тогда занижает).
  Значит, это не граница ни сверху, ни снизу, и ни одно печатаемое число на нём
  стоять не может. Расхождение поймано `verify_instances.py` на восьми
  естественных инстансах; `instance.evaluate` с тех пор зовёт исчерпывающий
  перебор. Верхняя оценка в `upper_bound_dp` этим не задета: она считает
  досягаемость при всех остальных пустых слотах, а это максимум из возможных,
  включая эффект освобождения гексов.

## Протокол прогона LLM (для оркестратора)

`llm_tasks.jsonl` — 290 строк: 145 инстансов × 2 варианта промпта. Поля:
`task_id`, `instance_id`, `family`, `size`, `variant`, `prompt`.

**Варианты промпта.** `assisted` — основной: в промпте выписано, какие вражеские
стеки достаёт каждый слот. Заявка работы про решение о **распределении**, поэтому
геометрию отдаём даром, чтобы модель тратила всё на интересующую нас часть; если
разрыв виден и здесь, списать его на арифметику гексов не выйдет. `raw` —
контраст: только координаты и правило расстояния, труднее, но смешивает
распределение с пространственным рассуждением, поэтому в заголовок результатов
не идёт.

Промпт самодостаточен: правила выписаны внутри, ссылок на файлы и слов
«сложность», «NP» в нём нет. Длина 3.9–5.7 тыс. символов.

**Как гнать.** Для каждой строки подать `prompt` модели, ответ записать в JSONL:

```json
{"task_id": "naturalM-k4-00::assisted", "model": "claude-fable-5", "response": "<сырой текст ответа>"}
```

`response` разбирать не нужно — скорер сам достанет JSON из обрамления. Поля
`latency_ms`, `prompt_tokens`, `completion_tokens` необязательны и переносятся в
результат. `model` группирует агрегаты.

Условия: температура 0 (или одинаковая для всех), без инструментов, без доступа к
симулятору, **один выстрел на инстанс** — меряем качество однократного решения, а
не результат поиска. Прогон с правом на поиск — это отдельный эксперимент, и
называть его надо отдельно.

```bash
python3 scripts/score_llm.py responses.jsonl -o results/llm.json
```

**Обработка невалидных ответов.** Нарушение бюджета — невалидный ответ, 0 баллов,
отдельный флаг. Ограничение по запасу это не оформление, а сама задача: если
перерасход обрезать, модель наберёт очки, игнорируя единственное ограничение,
которое делает задачу рюкзаком. Выбрасывать невалидные ответы нельзя тем более —
это молча вознаградит модель за отказ отвечать ровно там, где ей трудно. Чтобы
этот выбор нельзя было назвать причиной результата, скорер печатает сразу три
колонки: `strict` (основная), `valid_only`, `repaired`, плюс разбивку по видам
сбоя. Совпадают — значит выбор ни на что не влияет, и так и надо написать;
расходятся — это находка, и её надо опубликовать.

Разбор ответа снисходителен к упаковке и строг к содержанию: JSON достаётся из
прозы, из ```-обрамления, из объекта с лишними ключами; принимаются `[тип, число]`,
`{"type":…, "count":…}`, `null`, а для одноти́повых армий и голое целое. В самом
распределении не чинится ничего.
