## 1. Факты о модели, на которые опираются доказательства

Перечисляю явно, чтобы ни одно доказательство не опиралось на неявное допущение.

**M1 (соседи).** Для гекса `(x, y)` соседи: `(x±1, y)`, и в строках `y±1` — при чётном `y`
гексы `x` и `x+1`, при нечётном — `x−1` и `x` (`BattleHex.h:147-178`, MODEL.md §2).
Следствия, проверенные скриптом (проверка A): (a) у соседа `|dx| ≤ 1`, `|dy| ≤ 1`; поэтому
два гекса с `|dx| ≥ 2` или `|dy| ≥ 2` **не смежны**; (b) `(x, y)` всегда смежен с `(x, y+1)`
и с `(x+1, y)` — столбец и строка суть пути; (c) для чётной строки `y` тройки соседей
`{(x, y−1), (x+1, y), (x, y+1)}` и `{(x+1, y−1), (x−1, y), (x+1, y+1)}` попарно не смежны
(«чередующиеся тройки»); (d) отражение `y ↦ 2r − y` относительно любой строки `r` сохраняет
смежность (чётность строки сохраняется, а формулы для `y±1` симметричны).

**M2 (движение).** Немeлетающий стек ходит по BFS-пути через проходимые **незанятые** гексы
длины `≤ spd`; `WALK_AND_ATTACK` = дойти до гекса, смежного с целью, и ударить. Мёртвый стек
перестаёт занимать гекс. Занятый живым стеком гекс непроходим (R4). Летающих нет («no
abilities»).

**M3 (одно терминальное действие).** За раунд у стека одна активация; `WAIT` откладывает её
в `WAIT`-фазу, но терминальное действие (ход/атака/`DEFEND`) всё равно одно. Ударов за атаку —
один (фрагмент `H3-det-melee`).

**M4 (порядок).** `NORMAL`-фаза по убыванию `spd`, `WAIT`-фаза по возрастанию. Во всех
конструкциях ниже `spd` игрока `≥ 2 > 1 = spd` врага, так что межсторонних ничьих нет и
модельное правило совпадает с движковым. Под `(‡)` враг в `NORMAL`-фазе делает `WAIT` (ничего
не меняет), в `WAIT`-фазе — `DEFEND`. Следовательно: **любой не ждавший стек игрока бьёт до
любого `DEFEND`; ждавший — после** (враги медленнее, `WAIT`-фаза по возрастанию скорости).

**M5 (урон).** `dmg = max(1, ⌊c·d·f_att·f_def⌋)`, `c` — эффективное число существ атакующего в
момент удара. `DEFEND` только увеличивает защиту цели, т.е. только уменьшает `f_def`; значит
**любой удар ≤ номинала** (номинал — удар при исходной защите), и удар не ждавшего стека равен
номиналу. Стек игрока до своего удара никем не бит (враги не атакуют, ответный удар следует
за ударом), так что `c` при ударе = выделенное число существ.

**M6 (убийства).** Враг из одного существа с `hp = h` умирает ровно тогда, когда суммарный
урон по нему за раунд `≥ h` (пул `h`, overkill отбрасывается, `kills = 1 ⇔ D ≥ firstHPleft`).
Урон накапливается между ударами разных стеков.

**M7 (ответ).** Ответный удар бьёт только атакующего, врагам не вредит и на цель не влияет.
Для целевой функции он значим лишь тем, что может убить стек игрока и освободить гекс (M2).

**M8 (сертификат).** Действие стека описывается O(log(nm)) битами; распределение — `k` чисел.

**M9 (кодировка).** Числа в двоичной записи, `R` в унарной, доска перечислена гекс за гексом.

## 2. Лемма 2.1 (принадлежность NP) — доказано

**Утверждение.** `ARMY-ALLOCATION ∈ NP`.

**Доказательство.** Сертификат: распределение `(t_j, c_j)_{j=1..k}` (тип и число существ на слот,
`c_j` в двоичной записи, `≤ |вход|` бит каждое) и для каждого из `R` раундов и каждого слота
— действие: `WAIT`/`DEFEND`/`MOVE(h)`/`ATTACK(e, h)` с гексом `h` и индексом цели `e`; при `WAIT`
— ещё одно отложенное действие. Длина `O(k + R·k·log(nm + |D|))` = poly (`R` унарно, `k`, `nm`,
`|D|` ≤ длина входа, M9).

Проверка: (1) допустимость распределения — сравнение сумм двоичных чисел; (2) симуляция `R`
раундов: в каждом раунде сортировка `≤ k + |D|` стеков по `spd` (сравнение двоичных чисел),
для каждой активации BFS по графу из `nm` вершин (M2), затем арифметика урона в точных
рациональных числах со знаменателями `20·40` (M5), обновление пула `(fullUnits, firstHPleft)`
делением с остатком двоичных чисел (M6), ответный удар (M7); действия врага заданы `(‡)`
детерминированно. Каждый шаг полиномиален от длины входа; шагов `O(R·(k + |D|))`.
(3) Подсчёт ценности убитых — сумма произведений двоичных чисел, сравнение с `W`. ∎

**Согласованность с кодировкой.** (i) Унарность `R` необходима: при двоичном `R` сертификат
вида «действие на каждый раунд» имеет экспоненциальную длину, и принадлежность NP не
очевидна (задача, вероятно, попадает лишь в PSPACE). (ii) Двоичные `c_j`, `hp`, урон не
мешают: состояние стека — пара двоичных чисел, один удар обрабатывается арифметически, а не
«по одному существу». (iii) Для сильной NP-полноты (теорема 3) принадлежность NP при унарной
кодировке чисел следует из двоичной тривиально. (iv) `W ∈ ℤ_{>0}` двоично — сравнение
полиномиально. Скрытых допущений нет; единственная тонкость — что множество допустимых
действий стека конечно и перечислимо за poly, что даёт M2–M3.

## 3. Теорема 1 — доказано (слабая NP-полнота, PARTITION)

**Утверждение.** `ARMY-ALLOCATION` NP-полна уже при `R = 1`, одном типе существ у игрока, одном
существе в каждом вражеском стеке, без препятствий, на доске из одной строки.

Принадлежность NP — лемма 2.1. Трудность — сведение от PARTITION.

### 3.1 Конструкция

Вход PARTITION: `a_1, …, a_k ∈ ℤ_{>0}`, `Σ a_j = 2T`. Вопрос: есть ли `S ⊆ [k]` с `Σ_{j∈S} a_j = T`.

Экземпляр `ARMY-ALLOCATION`:

* Доска `1 × m`, `m = 5(k−1) + 2`, без препятствий; единственная строка `y = 0`.
* Слоты `k`; гекс развёртки слота `j`: `p_j = (5(j−1), 0)`.
* Тип игрока `P = (att 1, def 1, dmg 1/1, hp 1, spd 2)`, запас `B = T`, ценность 0.
* Враги: `E_j = (att 1, def 1, dmg 1/1, hp a_j, spd 1, value a_j)`, по одному существу, на
  гексе `(5(j−1)+1, 0)`, `j = 1..k`.
* `R = 1`, `W = T`.

Между `E_j` и `p_{j+1}` три пустых гекса (`5(j−1)+2, +3, +4`). Размер poly, числа `a_j`, `T`
двоично — сведение полиномиально.

### 3.2 Лемма о паросочетании достижимости (динамическая)

**Лемма 3.А.** В любой позиции, достижимой в любой партии, стек слота `j` может ударить только
`E_j`.

*Доказательство.* В одной строке гексовое расстояние равно `|dx|`, а BFS-расстояние ≥ гексового.
Гексы, смежные с `E_i`, — это `5(i−1)` и `5(i−1)+2`. Стек слота `j` никогда не двигался до
своего единственного действия (M3), стоит на `5(j−1)`; для `i ≠ j` расстояния до этих гексов:
`|5(j−1) − 5(i−1)| ≥ 5` и `|5(j−1) − 5(i−1) − 2| ≥ 3` (минимум 3 при `i = j−1`). Оба `> spd = 2`.
Ни смерть врагов, ни перемещения других стеков не уменьшают гексовое расстояние. ∎

Заметим, что лемма не использует занятости гексов — она чисто метрическая, поэтому
«динамика» (освобождение гексов) ей не вредит.

### 3.3 Корректность

**(⟹)** Пусть `Σ_{j∈S} a_j = T`. Распределение: `c_j = a_j` для `j ∈ S`, иначе `0`; всего `T = B`.
Игра: слоты по порядку (все `spd = 2`, порядок по индексу), слот `j ∈ S` бьёт `E_j`, стоя на
месте (`p_j` смежен с `E_j`). Стек не ждал ⇒ удар до `DEFEND` (M4): `Δ = 0`, урон
`max(1, ⌊a_j·1⌋) = a_j = hp(E_j)` ⇒ `E_j` погибает (M6), ответного удара нет. Убито ценности
`Σ_{S} a_j = T = W`. ✓

**(⟸)** Пусть распределение `(c_j)`, `Σ c_j ≤ T`, и партия убивают ценности `≥ T`. Пусть `S` —
множество убитых врагов. По лемме 3.А `E_j` бьёт только слот `j`, один раз (M3), с уроном
`≤ c_j` (M5: номинал `c_j·1`). Убит ⇒ `c_j ≥ a_j` (M6). Тогда
`T ≤ Σ_{S} a_j ≤ Σ_{S} c_j ≤ Σ_j c_j ≤ T`, значит `Σ_{S} a_j = T`. ✓ ∎

### 3.4 Тонкости

* Использована **разнотипность врагов** (`hp` и `value` различны); с одним типом врагов задача
  на этой семье тривиальна. Формулировка это допускает («single creature type in the
  player's army»).
* Ценность врага `a_j` **и** `hp = a_j`: любой из двух можно было бы заменить на 1/константу?
  Нет: с `value = 1` нужно было бы `W = |S|`, неизвестное; вариант «`hp = a_j`, `value = a_j`»
  — стандартный.
* Клэмп `max(1, ·)` не срабатывает (`c_j ≥ 1 ⇒ c_j·1 ≥ 1`), ноль существ — нет стека.
* Правило ничьих не задействовано (враг медленнее).

## 4. Предложение 1.1 — доказано с уточнённой формулировкой

**Формулировка статьи.** На семействе теоремы 1 — один тип у игрока, `R = 1`, `(‡)`, урон под
`(★)`, одно существо на вражеский стек, «matching reach structure» (слот `j` достигает ровно
одного врага `E_j`, каждый враг достигается ровно одним слотом) — задача решается за `O(k·B)`
времени и `O(B)` памяти, `B` — запас.

**Уточнение, которое я считаю необходимым.** Слово «reaches» надо определить. Предлагаю:
*слот `j` достигает `E` в стартовой позиции при всех занятых слотах, если существует гекс,
смежный с `E`, свободный и достижимый из `p_j` BFS-путём длины `≤ spd` по свободным гексам
(все `p_i`, все враги заняты).* Это **статическая** достижимость. Ниже показано, что
(a) верхняя оценка вообще не нуждается в структуре достижимости, (b) нижней хватает статической.
Поэтому предложение верно при статическом прочтении, и тем более при любом более сильном.
Ещё одно уточнение: `O(k·B)` — при единичной стоимости арифметики над числами входа (word-RAM);
`B` двоично, так что алгоритм псевдополиномиален, что и согласуется с теоремой 1.

**Уточнённое утверждение.** Пусть `d` — плоский урон типа игрока, `h_j` — `hp` врага `E_j`,
`v_j` — его ценность, `r_j := ⌈h_j / d⌉`. Тогда ответ «да» ⇔ существует `S ⊆ [k]` с
`Σ_{S} r_j ≤ B` и `Σ_{S} v_j ≥ W`; это 0/1-рюкзак, решаемый ДП за `O(k·B)` времени и `O(B)`
памяти.

### 4.1 Верхняя оценка (без предположений о геометрии)

**Лемма 4.А.** При одном типе игрока, `(★)`, `R = 1`, `(‡)`, одном существе на вражеский стек:
в любой партии для множества `S` убитых врагов выполнено `Σ_{S} r_j ≤ Σ_j c_j ≤ B`.

*Доказательство.* Для убитого `E_j` пусть `A_j` — множество слотов, чьи стеки ударили по нему.
Каждый стек бьёт не более одного раза (M3), так что `A_j` попарно не пересекаются. Удар стека
слота `i` наносит `≤ c_i·d` (M5, номинал под `(★)` равен `c_i·d`; клэмп `max(1,·)` не
превышает `c_i·d`, ибо `c_i·d ≥ 1`). Убит ⇒ `Σ_{i∈A_j} c_i·d ≥ h_j` (M6) ⇒ `Σ_{A_j} c_i ≥ h_j/d`,
а левая часть — целое, значит `≥ r_j`. Суммируя по `j ∈ S` и пользуясь дизъюнктностью:
`Σ_S r_j ≤ Σ_i c_i ≤ B`. ∎

Замечание: лемма не требует matching reach. Несколько слотов, бьющих одного врага (что
возможно при динамическом раскрытии гексов), не дают выгоды: стоимость убийства `E_j` в
существах всё равно `≥ r_j`.

### 4.2 Нижняя оценка (нужна статическая достижимость)

**Лемма 4.Б.** Пусть в стартовой позиции статическая достижимость — паросочетание `j ↔ E_j`.
Для любого `S` с `Σ_S r_j ≤ B` существует распределение и партия, убивающие ровно `S`.

*Доказательство.* Положим `c_j = r_j` для `j ∈ S`, `0` иначе. Для `j ∈ S` зафиксируем
статический путь `π_j` из `p_j` в свободный гекс `h_j`, смежный с `E_j`, длины `≤ spd`.
План: каждый слот `j ∈ S` при своей активации (не ждёт) идёт по `π_j` и бьёт `E_j`.

Осуществимость. Когда ходит `j`, занятыми могут быть: враги (часть мертва — только меньше
блокировок; `π_j` их и так не использует), ещё не ходившие слоты на своих `p_i` (статически
заняты, `π_j` их обходит), уже ходившие слоты `i ∈ S` на своих `h_i`. Покажем `h_i ∉ π_j` и
`h_i ≠ h_j`. Если бы `h_i` лежал на `π_j` (или совпадал с `h_j`), то префикс `π_j` до `h_i` —
статический путь длины `≤ spd` в свободный гекс, смежный с `E_i`, т.е. слот `j` статически
достигает `E_i`, `i ≠ j` — противоречие с паросочетанием. Итак, `π_j` и `h_j` свободны.
Урон: стек не ждал ⇒ удар до `DEFEND` (M4), `= r_j·d ≥ h_j` ⇒ `E_j` погибает (M6). ∎

### 4.3 Алгоритм

`dp[b]` = максимальная ценность при суммарной стоимости `≤ b`. Инициализация `dp ≡ 0`; для
`j = 1..k`, если `r_j ≤ B`, то для `b = B, B−1, …, r_j`: `dp[b] = max(dp[b], dp[b − r_j] + v_j)`.
Ответ «да» ⇔ `dp[B] ≥ W`. Время `O(k·B)`, память `O(B)`; `r_j` вычисляется одним делением.
Корректность — стандартный 0/1-рюкзак плюс леммы 4.А, 4.Б. ∎

### 4.4 Тонкости, которые автор мог упустить

1. **Определение «reaches».** Без слов «статически, при занятых слотах» утверждение
   двусмысленно; при статическом прочтении оно верно (показано). Если бы «reaches» понималось
   динамически (с учётом смертей/ходов), формулировка была бы сильнее и тоже верна.
2. **Одно существо на вражеский стек — существенно.** При `count_j ≥ 2` слот `j` с `c`
   существами убивает `min(⌊c·d/h_j⌋, count_j)` существ, целевая функция по слоту нелинейна
   и ДП становится `O(k·B·min(B, count))` или `O(k·B²)`; `O(k·B)` в общем случае не выходит.
   (Видимо, ровно это и было починено в раунде 10.)
3. **Многократные атакующие на одного врага** возможны при динамике, но безвредны (лемма 4.А).
4. Условие `(★)` можно ослабить до любого `Δ` — `r_j := min{c : max(1, ⌊c·d·f⌋) ≥ h_j}`
   вычислимо, монотонность по `c` сохраняется.

## 5. Лемма 3.2 (resource lemma) — доказано

**Утверждение.** `0 < μ < 1`, `D(c) = max(1, ⌊μc⌋)`. Если стеки размеров `c_1..c_r ≥ 1` наносят
одной цели не более `D(c_i)` каждый и суммарно `≥ 3`, то `Σ c_i ≥ 3`, с равенством ⇔ `r = 3`
и `c_1 = c_2 = c_3 = 1`.

*Доказательство.* Для любого `c ≥ 1`: `D(c) ≤ c`, причём равенство ⇔ `c = 1`. Действительно,
`D(1) = max(1, ⌊μ⌋) = 1`; при `c ≥ 2`: `⌊μc⌋ ≤ μc < c` и `1 < c`, так что `D(c) < c`.
Тогда `3 ≤ Σ (урон_i) ≤ Σ D(c_i) ≤ Σ c_i`. Если `Σ c_i = 3`, все неравенства — равенства:
`D(c_i) = c_i` для всех `i` ⇒ все `c_i = 1` ⇒ `r = Σ c_i = 3`. Обратно, три одиночки дают
`Σ c_i = 3`. ∎ (Скрипт: перебор `μ = 0.3`, `c ≤ 11`, `r ≤ 4` — OK.)

Замечание: `μ > 0` не нужно для доказательства; `μ < 1` существенно.

## 6. Теорема 3 и следствие 3.1 — доказано (сильная NP-трудность, один тип, planar X3C)

**Утверждение.** `ARMY-ALLOCATION` сильно NP-трудна уже при `R = 1`, одном типе существ у игрока,
одном существе на вражеский стек, всех врагах одного типа ценности 1, плоском уроне, без
способностей, со статическими непроходимыми гексами как единственным элементом рельефа.
С леммой 2.1 — сильно NP-полна. **Следствие 3.1:** то же при фиксированном распределении «по
одному существу в каждый слот»; `BATTLE-PLAY` сильно NP-трудна на однотипных экземплярах.

### 6.1 Почему конструкция вынуждена быть такой

Полезно объяснить, откуда берётся трудность, потому что это подсказывает и гаджеты, и
опасности. При `R = 1` и `(‡)` каждый стек игрока — один удар. Если бы достижимость была
**статической** (кто кого может ударить не зависит от хода партии), задача с одним типом
игрока и одинаковыми врагами свелась бы к `b`-паросочетанию в двудольном графе «слоты —
враги» (враг требует фиксированного числа ударов), что полиномиально. Значит, трудность
обязана исходить из **динамики**: (i) мёртвый враг освобождает гекс и открывает проход
(R4), (ii) стек, вставший у врага, блокирует гекс. Дальше: одинаковые враги и ценность 1 —
значит, нужно, чтобы «какие враги умрут» кодировало выбор; выбор в задаче — это распределение
(какие слоты заполнены) и назначение целей. Одному врагу — три удара одиночек (клэмп + кап
`f_def`), одному элементу — один слот: тогда враг-множество `E_S` умирает ⇔ его три элемента
все ударили именно по нему, а бюджет запрещает всё остальное. Отсюда конструкция.

### 6.2 Числа

* Тип игрока `P = (att 1, def 1, dmg 1/1, hp 2, spd σ)`, где `σ` = число гексов доски.
* Тип врага `Q = (att 1, def 29, dmg 1/1, hp 3, spd 1, value 1)`.
* Удар стека из `c` существ по `Q`: `Δ = 1 − 29 = −28`, `f_def = 1 − min(28/40, 7/10) = 3/10`
  (кап достигнут), `dmg = max(1, ⌊3c/10⌋) =: D(c)`. **После `DEFEND`** защита `29 + max(1, ⌊29/5⌋)
  = 34`, `Δ = −33`, `f_def` по-прежнему `3/10` — кап поглощает бонус, урон **точно** `D(c)`
  независимо от фазы удара. `D(1) = D(2) = … = D(6) = 1`, `D(7) = 2`, `D(10) = 3`.
* Ответ `Q → P`: `Δ = 0`, урон `max(1, ⌊1·1⌋) = 1 < 2 = hp(P)` ⇒ **ни одно существо игрока не
  погибает** (у стека `firstHPleft = 2`).

### 6.3 Схема: деревья элементов и Т-развязки множеств

Вход: planar X3C `(X, C)`, `|X| = 3q`, `C ⊆ binom(X, 3)`, граф инцидентности `G` (элементы —
множества) планарен. NP-полнота: Dyer–Frieze 1986 (Planar 3DM NP-полна; 3DM — частный случай
X3C с тем же графом инцидентности). Числовых параметров нет ⇒ всякая полиномиальная
редукция с poly-ограниченными числами даёт сильную NP-трудность.

Требования к доске (абстрактно):

* **(T1)** Для каждого `x ∈ X` — связное множество проходимых гексов `T(x)` («дерево» `x`),
  содержащее гекс развёртки `p_x`. Для `x ≠ y` множества `T(x)`, `T(y)` **не пересекаются и
  не смежны** (никакой гекс одного не соседствует с гексом другого).
* **(T2)** Для каждого `S ∈ C` — гекс `E_S` (враг `Q`, одно существо), проходимые соседи
  которого — ровно три гекса `a_{x,S} ∈ T(x)`, по одному на каждый `x ∈ S`, **попарно не
  смежные**; остальные три соседа непроходимы. Гексы `E_S`, `E_{S'}` не смежны.
* **(T3)** Все прочие гексы непроходимы. `p_x` не смежен ни с каким `E_S` (удобно, не
  обязательно).

Слоты: `k = 3q`, по одному на элемент, `p_x`. Запас `B = 3q`. `W = q`. `R = 1`.

Зачем попарная несмежность в (T2): если бы `a_{x,S}` и `a_{y,S}` были смежны, стек `y` мог бы
перейти в `T(x)` без смерти `E_S`, и деревья перестали бы быть изолированными.

### 6.4 Реализация на гексовой сетке (полиномиальная укладка)

**Шаг 1: представление видимости.** Планарный граф `G` (при необходимости — по компонентам)
имеет слабое представление видимости на целочисленной сетке `O(N) × O(N)`, `N = |X| + |C|`,
вычислимое за линейное время (Tamassia–Tollis 1986; Rosenstiehl–Tarjan 1986): вершина `v` —
горизонтальный отрезок («бар») на строке `Y_v` от колонки `X_v^a` до `X_v^b`, ребро `uv` —
вертикальный отрезок на колонке `X_{uv} ∈ [X_u^a, X_u^b] ∩ [X_v^a, X_v^b]` между строками `Y_u`
и `Y_v`, не пересекающий других баров. Два ребра, входящие в один бар с одной стороны, имеют
разные колонки; с разных сторон могут иметь одну.

**Шаг 2: масштаб 6.** Крупная точка `(X, Y)` ↦ мелкий гекс `(6X, 6Y)`. Бар `v` ↦ гексы
`(x, 6Y_v)`, `6X_v^a ≤ x ≤ 6X_v^b` (связен по M1(b)). Ребро ↦ гексы `(6X_{uv}, y)` между
строками (связен по M1(b)), примыкает к барам концов (смежность по столбцу). Разные объекты
на разных крупных линиях отстоят на `≥ 6` по одной из координат и потому **не смежны** (M1(a)).
Объекты, не пересекающиеся в представлении видимости (ребро не режет чужой бар), после
масштабирования не смежны: если ребро в колонке `X` проходит строку `Y'` чужого бара, то бар
не содержит колонку `X`, т.е. его концы отстоят на `≥ 1` крупную = `≥ 6` мелких колонок.

**Шаг 3: деревья элементов.** `T(x)` := бар `x` ∪ рёбра `(x, S)`, `S ∋ x`, обрезанные у строки
`6Y_S ∓ 5` (входя в «приватную зону» множества), ∪ дорожка адаптера (шаг 4). `p_x` — любой гекс
бара `x`. Свойство (T1): разные элементы — разные бары и разные рёбра ⇒ несмежность по шагу 2;
адаптерные дорожки лежат в приватных зонах, см. ниже.

**Шаг 4: приватная зона и адаптер множества `S`.** Пусть бар `S` на строке `r = 6Y_S` (чётной!)
с колонками `[6X_S^a, 6X_S^b]`, три ребра входят в колонках `c_1 ≤ c_2 ≤ c_3` (кратны 6) сверху
(`A`, гекс входа `(c_i, r−5)`) или снизу (`B`, `(c_i, r+5)`). **Зона** — строки `[r−5, r+5]`,
колонки `[6X_S^a − 5, 6X_S^b + 5]`: по шагу 2 в ней нет чужих объектов (другие бары на строках
`≠ r` отстоят на `≥ 6`; чужие рёбра в колонках внутри пролёта бара не пересекают строку `r`,
значит целиком выше `r−6` или ниже `r+6`; чужие рёбра вне пролёта — в колонках `≤ 6X_S^a − 6`
или `≥ 6X_S^b + 6`, а дорожки ниже используют колонки `≥ c_1 − 2 ≥ 6X_S^a − 2` и `≤ c_3`).

Внутри зоны ставим `E_S` и три попарно несмежные дорожки от входов к трём чередующимся
соседям `E_S`. Используем «Т-развязку»: при `E_S = (c, r)` (чётная строка) тройка
`{(c, r−1), (c+1, r), (c, r+1)}` = {TL, R, BL} даёт рукава «столбец `c` вверх», «столбец `c`
вниз», «строка `r` вправо от `c+1`»; тройка `{(c+1, r−1), (c−1, r), (c+1, r+1)}` = {TR, L, BR}
при `E_S = (c−1, r)` даёт рукава «столбец `c` вверх/вниз» и «строка `r` влево от `c−2`».
Рукава попарно не смежны (M1(c) для концов; остальные гексы рукавов отстоят на `≥ 2` по одной
координате). Шаблоны (обозначения: `V(c, y_0→y_1)` — столбец, `H(y, x_0→x_1)` — строка):

* **Совпадающие колонки** (`(c, A)`, `(c, B)`, `(c', s')`): `A ↦ V(c, r−5→r−1)`, `B ↦ V(c, r+5→r+1)`;
  если `c' > c`: `E_S = (c, r)`, третья ↦ `V(c', вход→r) + H(r, c'−1→c+1)`; если `c' < c`:
  `E_S = (c−1, r)`, третья ↦ `V(c', вход→r) + H(r, c'+1→c−2)`.
* **Три разные колонки**, `s_2 = A` (иначе отразить относительно строки `r`, M1(d), и
  отразить результат обратно): вторая ↦ `V(c_2, r−5→r−1)` (рукав N).
  – `s_1 = B`: `E_S = (c_2, r)`; первая ↦ `V(c_1, r+5→r+3) + H(r+3, c_1+1→c_2) + V(c_2, r+2→r+1)`
    (рукав S); третья ↦ `V(c_3, вход→r) + H(r, c_3−1→c_2+1)` (рукав E).
  – `s_1 = A, s_3 = B`: `E_S = (c_2−1, r)` (Т смотрит на запад); третья ↦
    `V(c_3, r+5→r+3) + H(r+3, c_3−1→c_2) + V(c_2, r+2→r+1)` (BR); первая ↦
    `V(c_1, r−5→r) + H(r, c_1+1→c_2−2)` (L).
  – `s_1 = s_3 = A`: `E_S = (c_2, r)`; первая обходит слева: `V(c_1, r−5→r−3) + H(r−3, c_1−1→c_1−2)
    + V(c_1−2, r−2→r+3) + H(r+3, c_1−1→c_2) + V(c_2, r+2→r+1)` (рукав S); третья ↦
    `V(c_3, r−5→r) + H(r, c_3−1→c_2+1)` (рукав E).

Все дорожки лежат в строках `[r−5, r+5]`, колонках `[c_1−2, c_3]` (вход в зону), поэтому
не смежны ни с чем чужим; попарная несмежность дорожек и то, что у `E_S` ровно три проходимых
соседа (концы дорожек), проверены скриптом для всех 12 конфигураций (8 троек сторон + 4 с
совпадающей колонкой) — проверка B. Ручная проверка для `AAA`: `(c_2, r−1)` vs `(c_2+1, r)` —
у гекса `(c_2+1, r)` (чётная строка) соседи в строке `r−1` суть `(c_2+1, r−1), (c_2+2, r−1)`,
так что не смежны; аналогично снизу; горизонтальные отрезки на строках `r±3` отстоят от строки
`r` на 3.

Дорожка, входящая из ребра элемента `x`, включается в `T(x)`; конец дорожки — `a_{x,S}`.
Свойства (T2) выполнены. Разные `E_S` лежат в разных зонах ⇒ не смежны. Все остальные гексы
прямоугольника объявляем непроходимыми (T3). Размер доски `O(N) × O(N)` мелких гексов, все
числа `≤ poly(N)`. Укладка полиномиальна.

Об ориентации: шаблоны используют соглашение «чётные строки сдвинуты вправо» (M1). При
противоположном соглашении рукава N/S в столбце `c` надо сочетать с рукавом **влево**, а не
вправо (тройка `{(c, r−1), (c−1, r), (c, r+1)}`); в остальном то же самое.

### 6.5 Корректность

Пусть `G_3(X, C)` — построенный экземпляр.

**Лемма 6.А (изоляция).** Пока живы все `E_S` с `x ∈ S`, компонента связности гекса `p_x` в
графе проходимых гексов (без учёта занятости) равна `T(x)`.

*Доказательство.* Проходимые гексы — `∪_y T(y)` плюс гексы мёртвых врагов. `T(x)` смежен только
с гексами `E_S`, `x ∈ S` (T1, T2): его соседи вне `T(x)` — либо непроходимы, либо это `E_S` с
`a_{x,S} ∈ T(x)`, что означает `x ∈ S`. Если все такие `E_S` живы, они непроходимы, и `T(x)`
замкнут. ∎

**Лемма 6.Б (бюджет).** Пусть распределение `(c_x)`, `Σ c_x ≤ 3q`, и партия убивает `t` врагов.
Тогда `t ≤ q`; если `t = q`, то каждый слот получил ровно одно существо, каждый стек ударил
ровно один раз, и у каждого убитого `E_S` множество ударивших `A_S` состоит ровно из трёх
слотов (одиночек), причём `{A_S}` — разбиение `X`.

*Доказательство.* Удар стека размера `c` по `Q` равен `D(c)` в любой фазе (§6.2). `A_S`
попарно дизъюнктны (M3). `E_S` убит ⇒ суммарный урон `≥ 3` ⇒ (лемма 3.2) `Σ_{A_S} c_x ≥ 3`.
Значит `3t ≤ Σ_S Σ_{A_S} c_x ≤ Σ_x c_x ≤ 3q`, `t ≤ q`. При `t = q` всё — равенства: каждый
`Σ_{A_S} c_x = 3` ⇒ (лемма 3.2) три одиночки; `Σ_x c_x = 3q = k` и все существа в `∪ A_S` ⇒
каждый из `3q` слотов имеет ровно одно существо и лежит ровно в одном `A_S`. ∎

**Лемма 6.В (заключение).** В ситуации леммы 6.Б с `t = q`, если убитые враги — `E_{S_1}, …,
E_{S_q}` в порядке гибели, то `A_{S_i} = S_i` для всех `i` (как множества элементов).

*Доказательство.* Индукция по `i`. Пусть `A_{S_j} = S_j` для `j < i`. Возьмём `x ∈ A_{S_i}`.
Стек `x` ударил `E_{S_i}` с гекса `h`, смежного с `E_{S_i}`, т.е. `h = a_{y,S_i}` для некоторого
`y ∈ S_i` (T2). До этого стек `x` не двигался (M3), значит `h` достигнут путём из `p_x` по
проходимым гексам в момент удара `≤ t_i`. Утверждаю: `x ∉ S_j` при `j < i`. Иначе `x ∈ S_j =
A_{S_j}`, т.е. стек `x` уже ударил `E_{S_j}` — а он бьёт лишь раз. Итак, в момент удара все
`E_S` с `x ∈ S` живы (мертвы лишь `E_{S_j}`, `j < i`, и `x ∉ S_j`) — по лемме 6.А путь лежит в
`T(x)`, значит `a_{y,S_i} ∈ T(x)`, откуда `y = x` (T1) и `x ∈ S_i`. Итак `A_{S_i} ⊆ S_i`;
`|A_{S_i}| = 3 = |S_i|` ⇒ равенство. ∎

**Теорема 3 (⟹).** Пусть `C' = {S_1, …, S_q}` — точное покрытие. Распределение: одно существо
в каждый слот (`3q = B`). Для `x` пусть `S(x)` — единственное множество `C'` с `x ∈ S(x)`. План:
при активации (все `spd = σ`, порядок по слоту) стек `x` идёт по пути внутри `T(x)` от `p_x`
до `a_{x,S(x)}` и бьёт `E_{S(x)}`. Осуществимость: в момент хода `x` каждый чужой стек `y` стоит
либо на `p_y`, либо на `a_{y,S(y)}` — оба в `T(y)`, а `T(y) ∩ T(x) = ∅` (T1); гексы врагов на пути
не лежат. Значит путь свободен, длина `≤ σ = spd`, гекс `a_{x,S(x)}` свободен. Урон каждого
удара `D(1) = 1`; по каждому `E_S`, `S ∈ C'`, приходят ровно три удара (от трёх элементов `S`)
— после третьего пул `3` исчерпан, враг мёртв (M6). Ответ первому атакующему — 1 урона, никто
не гибнет. Итого убито `q = W` врагов ценности 1. ✓

**Теорема 3 (⟸).** Если некоторое распределение с `Σ c_x ≤ 3q` и партия дают ценность `≥ q`,
то `t ≥ q` убитых; по лемме 6.Б `t = q` и `{A_S}` — разбиение `X` на тройки; по лемме 6.В
`A_{S_i} = S_i`; значит `S_1, …, S_q` попарно дизъюнктны и покрывают `X` — точное покрытие. ✓

**Ограничения формулировки.** Один тип игрока ✓; один тип врагов, одно существо, ценность 1 ✓;
плоский урон ✓; способностей нет ✓; рельеф — только статические непроходимые гексы ✓;
`R = 1` ✓; числа `≤ poly(N)` ⇒ сильная трудность ✓; с леммой 2.1 — сильная NP-полнота ✓. ∎

**Следствие 3.1.** Тот же экземпляр с фиксированным распределением «по одному в слот».
(⟹) — тот же свидетель. (⟸) — лемма 6.Б применима (`Σ c_x = 3q`), далее лемма 6.В. Так как
все стеки — одиночки, лемма 3.2 даже не нужна: удар одиночки ровно 1, три удара на врага.
`BATTLE-PLAY` содержит эту семью. ∎

### 6.6 Тонкости и места возможных ошибок

1. **Динамика через мёртвых врагов.** Ключевое место: после смерти `E_S` деревья элементов `S`
   соединяются. Доказательство держится на том, что **все три** элемента `S` уже отходили
   (лемма 6.В), — иначе стек `z ∈ S`, не ходивший, мог бы пройти сквозь `E_S` в `T(x)` и
   ударить `E_{S'}` с `x ∈ S'`, `z ∉ S'`. При `hp = 3` и трёх одиночках это невозможно; при
   ином балансе (например, если бы стек мог убивать врага в одиночку) конструкция бы
   рухнула. Это то, что должен покрывать инвариант «Confinement» автора.
2. **Кап `f_def`.** Если у автора `Δ` не достигает капа (`|Δ| < 28`), бонус `DEFEND` меняет
   урон крупных стеков (только вниз — безопасно) и **не** меняет урон одиночки (клэмп). Верно
   при любом `Δ < 0`, но проще ставить кап.
3. **Смерть атакующих** от ответного удара освобождала бы `a_{x,S}`; в моём доказательстве
   занятость гексов доступа не используется, поэтому безразлично. Если автор опирается на
   «три различных гекса доступа заняты тремя атакующими», ему нужна лемма «никто не гибнет».
4. **Чётность строки `E_S`.** Чередующиеся тройки записаны для чётной строки; при масштабе 6
   строки баров чётны. Если автор ставит врагов в нечётные строки, тройки другие
   (`{(x−1, y−1), (x+1, y), (x−1, y+1)}` и `{(x, y−1), (x−1, y), (x, y+1)}`).
5. **Отражение относительно строки** — симметрия сетки, а **отражение относительно столбца —
   нет** (меняется направление сдвига). Если адаптеры выведены из одного шаблона
   «поворотами/отражениями», надо проверить, что использованы лишь отражения по строке.
6. **Зона множества и чужие рёбра**: ребро, входящее в *соседний* бар той же строки с той же
   стороны, может проходить рядом с зоной; масштаб 6 и границы зоны `[c_1−2, c_3]` это
   покрывают, при масштабе 3 — уже нет (обходной рукав AAA уходит на 2 колонки левее `c_1`).
7. `p_x` смежен с `E_S`? В моей укладке нет (бар вне зоны). Если бы был, ничего не ломается
   (удар «с места» — частный случай), но лемма 6.А формулируется чуть аккуратнее.
8. Планарность нужна лишь для непересечения деревьев; для непланарного X3C потребовался бы
   гаджет пересечения, которого у этой механики, по-видимому, нет (два дерева при пересечении
   неизбежно смежны). Утверждение статьи корректно ограничено planar X3C.

## 7. Теорема 4, следствия 4.1–4.2 и теорема 2 — доказано (3-PARTITION)

**Теорема 4.** `ARMY-ALLOCATION` сильно NP-трудна уже при `R = 1`; без препятствий и
способностей; каждый тип игрока запаса 1, одно существо на вражеский стек; открытая
прямоугольная доска `6 × (4m+2)`; и полной достижимости — в стартовой позиции при всех
занятых слотах каждый стек игрока может атаковать каждого врага.
**Следствие 4.1:** то же при заданном распределении. **Следствие 4.2:** то же с целевой
функцией «снятые очки здоровья» и порогом `W_hp = mT`.
**Теорема 2** (`R = 1`, без препятствий и способностей, все типы запаса 1) — частный случай
теоремы 4 (её экземпляры удовлетворяют всем условиям теоремы 2).

### 7.1 Конструкция

Вход 3-PARTITION: `a_1..a_{3m}`, `T`, `Σ a_i = mT`, `T/4 < a_i < T/2`. Сильно NP-полна, поэтому
считаем `T ≤ poly(m)`.

* Доска `6` строк (`y = 0..5`) × `4m+2` колонок (`x = 0..4m+1`), без препятствий.
* Слоты `k = 3m`, `p_j = (j−1, 0)` (нужно `3m ≤ 4m+2` ✓).
* Типы игрока `P_i = (att 1, def 1, dmg a_i/a_i, hp 1, spd s)`, запас 1 каждый, `s = 4m + 12`.
* Враги `E_l`, `l = 0..m−1`: тип `Q = (att 1, def 1, dmg 1/1, hp T, spd 1, value 1)`, одно
  существо, на гексе `(4l+2, 4)`.
* `R = 1`, `W = m`.

Размер `O(m)` гексов, числа `≤ max(T, 4m+12)` — poly ⇒ сильная трудность.

### 7.2 Геометрия

Соседи `E_l = (4l+2, 4)` (чётная строка): `(4l+1, 4), (4l+3, 4), (4l+2, 3), (4l+3, 3), (4l+2, 5),
(4l+3, 5)`. Соседства разных врагов не пересекаются (шаг 4 по `x`, соседи в колонках
`4l+1..4l+3`). Колонки `4l` и `4l+1` в строках 3–5 (для `l = 0..m`) **никогда** не являются
соседями врагов («коридоры»); строки 1 и 2 целиком свободны от врагов и их соседей.

**Лемма 7.А (магистраль).** Пусть заняты: враги (любые из них живы), стеки на некоторых `p_j`,
и стеки на некоторых гексах-соседях врагов. Тогда из любого `p_j` (стек на нём) до любого
свободного соседа любого `E_l` есть путь по свободным гексам длины `≤ 4m + 11`.

*Доказательство.* `(j−1, 0) → (j−1, 1) → (j−1, 2)` (M1(b), строки 1–2 свободны). По строке 2 до
нужной колонки. Далее к соседу `h` врага `E_l`:
– `h = (4l+2, 3)` или `(4l+3, 3)`: оба смежны со строкой 2 (нечётная строка 3: соседи сверху
`(x−1, 2), (x, 2)`), шаг вниз.
– `h = (4l+1, 4)`: через коридор `(4l, 2) → (4l, 3) → (4l, 4) → (4l+1, 4)` (столбец, потом строка).
– `h = (4l+3, 4)`: через `(4l+4, 2) → (4l+4, 3) → (4l+4, 4) → (4l+3, 4)` (колонка `4l+4 ≤ 4m`
  существует и коридорна).
– `h = (4l+2, 5)`: `(4l, 2) → (4l, 3) → (4l, 4) → (4l, 5) → (4l+1, 5) → (4l+2, 5)` (строка 5).
– `h = (4l+3, 5)`: `(4l+4, 2) → (4l+4, 3) → (4l+4, 4) → (4l+4, 5) → (4l+3, 5)`.
Все промежуточные гексы — строки 1–2 или коридоры, они не заняты по условию. Длина
`≤ 2 + (4m+1) + 6 ≤ 4m + 11 < s`. ∎

**Полная достижимость** в стартовой позиции: все соседи врагов свободны, лемма 7.А. ✓
(Скрипт проверяет это BFS'ом для `m ≤ 2`.)

### 7.3 Корректность (объектив «убитые существа»)

**(⟹)** Пусть `[3m] = G_0 ⊔ … ⊔ G_{m−1}`, `|G_l| = 3`, `Σ_{G_l} a_i = T`. Распределение: тип `P_i`
в слот `i`. План: при активации (все `spd = s`, порядок по слотам) стек `i ∈ G_l` идёт по пути
леммы 7.А к ещё свободному соседу `E_l` (их 6, занято `≤ 2` предыдущими из `G_l`) и бьёт `E_l`.
Занятость в момент хода: неходившие слоты на `p`, ходившие — на соседях врагов — ровно условие
леммы 7.А. Удар до `DEFEND`, `Δ = 0`, урон `a_i` (номинал). Первые два удара по `E_l` дают
`< T` (каждый `a_i < T/2`), враг жив, отвечает первому (урон 1, стек-одиночка с `hp 1`
погибает — освобождает гекс, безразлично); третий удар доводит сумму до `T` ⇒ `E_l` погибает
(M6). Убито `m = W`. ✓

**(⟸)** Пусть партия убила все `m` врагов (ценность `≥ m` при `m` врагах ценности 1). `A_l` —
слоты, бившие `E_l`, попарно дизъюнктны (M3); удар слота с типом `P_i` `≤ a_i` (M5; при
ударе стек цел — M5). `E_l` убит ⇒ `Σ_{A_l} a_i ≥ T`. Суммируем: `mT ≤ Σ_l Σ_{A_l} a_i ≤ Σ_i a_i
= mT` ⇒ все равенства: каждый тип в каком-то `A_l`, `Σ_{A_l} a_i = T`, `{A_l}` — разбиение
`[3m]`. Из `T/4 < a_i < T/2`: `|A_l| = 3`. Это 3-разбиение. ✓ ∎

### 7.4 Следствие 4.1 (распределение задано)

Фиксируем `P_i` в слоте `i`. (⟹) — тот же план. (⟸) — тот же подсчёт (он не использовал
свободы распределения). ∎

### 7.5 Следствие 4.2 (снятые очки здоровья, `W_hp = mT`)

Определение: `absorbed_l` = сумма фактических уменьшений пула `E_l`, overkill отброшен; при
накоплении ударов `absorbed_l = min(T, delivered_l)`, где `delivered_l` — сумма урона ударов по
`E_l`. `delivered_l ≤ Σ_{A_l} a_i` (M5).
(⟹) План §7.3 даёт `delivered_l = T` без overkill ⇒ `Σ absorbed = mT`. ✓
(⟸) `mT ≤ Σ_l absorbed_l ≤ Σ_l delivered_l ≤ Σ_l Σ_{A_l} a_i ≤ mT` ⇒ равенства: `absorbed_l =
delivered_l` (нет overkill, т.е. `delivered_l ≤ T`), `Σ_l delivered_l = mT` при `m` слагаемых
`≤ T` ⇒ все `= T` ⇒ `Σ_{A_l} a_i = T`, разбиение на тройки как выше. ✓ Обе версии
(распределение свободно/задано). ∎

### 7.6 Теорема 2

Экземпляры §7.1: `R = 1`, без препятствий, без способностей, каждый тип запаса 1 ⇒ теорема 2
— следствие теоремы 4. (Самостоятельная более простая укладка — то же на доске `7 × 4m` с
магистралью в строках 4–5 — не нужна.) ∎

### 7.7 Тонкости

1. **Накопление занятых соседей.** Свидетелю нужно, чтобы третий атакующий нашёл свободный
   сосед `E_l` **и путь к нему**; путь через магистраль и коридоры не пересекает соседей
   врагов, поэтому занятость двух соседей не мешает. Если автор ведёт атакующих «напрямую»
   через гексы-соседи, третьему может быть перекрыт единственный доступ.
2. **Полная достижимость определена статически** («в стартовой позиции при всех занятых
   слотах»); динамически она может теряться (блокировка) — но это не нужно ни одному
   направлению.
3. Смерть одиночки-атакующего от ответа (`hp 1`, урон ответа 1) — безвредна; можно взять
   `hp 2` и избежать смертей вообще.
4. `3m ≤ 4m + 2` — верно при всех `m ≥ 1`; при `m = 1` слоты в колонках 0–2, враг в `(2, 4)`.
5. Условие `T/4 < a_i < T/2` — часть определения 3-PARTITION; без него `|A_l| = 3` не
   следует, но и не нужно для «да ⇔ да»: `{A_l}` — разбиение на группы суммы `T` любого
   размера — это уже вариант задачи, всё ещё сильно NP-трудный; всё равно оставляю
   стандартное условие.
6. Одинаковые `a_i` дают одинаковые кортежи типов; типы — записи списка, различимость через
   номер, целевая функция читает лишь ценности врагов.
